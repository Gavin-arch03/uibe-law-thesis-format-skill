# 迁移到其他学校 / 学院

本 skill 内置 `uibe-law-2020` 一个 profile，但脚本与规则结构是通用的。换学校只需新增一个 profile + 一份 reference，不需改代码。

## 一、profile 是什么

`assets/profiles/*.json` 是机器可读的规则集，`check_docx.py --profile <id>` 直接读它。字段含义见 `assets/profiles/uibe-law-2020.json` 的注释性键名：

| 键 | 作用 |
|---|---|
| `page.margins_cm` / `tolerance_cm` | 页边距校验与容差 |
| `styles.*` | 各类段落的字体字号行距，`check_docx.py` 用它比对 |
| `parts_order` | 12 个组成部分顺序 |
| `toc.*` | 标题层级、禁止四级编号、标题最短字数、每页标题上限 |
| `footnote.*` | 编号方式、引用词、页码要求、期刊是否出现"卷" |
| `reference_list.*` | 分组、括号类型、是否禁页码、排序方向、数量下限 |
| `content.*` | 摘要字数、关键词分隔符、结论是否带章号、正文字数下限 |
| `known_conflicts` | 同一单位多份文件互相矛盾时的裁决记录 |

## 二、新增一个 profile 的步骤

1. **收集文件**：学校研究生院的总规范 + 学院（系）的细则 + 一份官方格式示例（最好是 Word，其次是 PDF）。
2. **用脚本量化示例**，不要靠肉眼估：

   ```bash
   python scripts/pdf_probe.py layout 示例.pdf --pages 11-25
   ```

   得到实测页边距、字号众数、行距众数、字体。**示例的实测值优先于文本描述**——学校文件里写的 3.6cm 常常与示例实际排版不符（本项目就遇到了）。
3. **找出文件之间的冲突**。常见冲突点：
   - 结论是否带章号（规范说"不加章号"，示例却写"第6章 结论"）
   - 脚注按页重编还是全文连续
   - 参考文献用 GB/T 7714 还是《法学引注手册》式
   - 正文行距 22 磅 vs 20 磅
   - 目录条目字体黑体 vs 宋体
   - 关键词分隔符「；」vs「，」
4. **裁决并记录**。裁决原则：
   - 学院细则 > 学校总规范（学校规范通常自带"各培养单位可另行制订"的授权条款，去原文里找到这句话，它就是依据）
   - 专管某事项的文件 > 综合示例文件（体例问题归《…体例》，版面问题归《…格式示例》）
   - 仍无法裁决时，取**样本库中的多数做法**，并在 `known_conflicts` 里写明
5. **写 profile JSON**，字段不必求全，`check_docx.py` 缺失的键会跳过。
6. **写一份 `references/<profile>.md`**，用自然语言记下规则与裁决理由。
7. **用一份真实论文验证**：

   ```bash
   python scripts/check_docx.py 论文.docx --profile 新profile
   ```

## 三、从样本库反推规则（没有官方示例时）

若拿不到官方格式示例，可以用往届论文反推，但必须先做版本判定，否则会把知网裁边版的假参数当真：

```bash
# 1. 先判定每篇 PDF 是否可信
python scripts/pdf_probe.py version 某篇.pdf

# 2. 批量分析整个集合，报告里会标出「可作排版范本」的篇目
python scripts/analyze_collection.py --collection <集合key> --out 报告.md
```

**关键判据**：学校提交版恒为 A4（210×297mm）、正文 12pt；知网裁边版常见 197–206 × 288–294mm、正文 10.2/10.5pt，还有 `ËÎÌå`（宋体 GBK 乱码）、`ºÚÌå`（黑体）这类字体名。只有 A4 版能用来读排版参数。

结构、逻辑链、引注体例则**任何版本都可信**——裁边只影响版面，不影响内容和引注。

## 四、非中文语种 / 非法学学科

- 英文脚注本 skill 走 Bluebook，只适用于法学。其他学科请替换 `references/citation-*.md` 的英文部分
- 理工科的图表规范、公式编号远比法学复杂，`uibe-law-2020` profile 的图表述规则不能直接套用
- `check_docx.py` 的检查项是通用骨架，学科特异的检查（如公式编号连续、三线表）需自行扩展 `check()` 函数

## 五、常见坑

| 坑 | 表现 | 处理 |
|---|---|---|
| 把知网版当下载的论文原文 | 字号 10.5pt、页面 199×290mm | 先跑 `pdf_probe.py version` |
| 直接信学校文件的文本参数 | 页边距写 3.6cm，实际示例是 2.8cm | 量示例，以示例为准 |
| CSL 硬套法学体例 | 生成的脚注没有页码、期刊带"卷"号 | 法学体例无现成 CSL，用 `gen_references.py` 拼装后手改 |
| Zotero 元数据不全就直接生成 | 参考文献缺出版社、缺期号 | `gen_references.py` 会在 stderr 列出待补字段，先回 Zotero 补齐 |
| 只改样式不改目录 | 目录页码与正文不一致 | 目录必须用 Word「引用→目录」自动生成 |
